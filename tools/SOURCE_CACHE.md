# 来源失效与最后成功数据

`gen_rulesets.py --source-cache .source-cache --source-report source-status.json`
按完整 URL（含数据集查询参数）保留一份最后验证成功的原始输入。
覆盖文本 HTTP、二进制 MRS 和 Kelee 原生 mihomo HTTP provider。
同一轮两个平台使用同一份来源快照；Kelee Clash/Loon 分别判断。

- 网络、空响应、HTML、编码、JSON/规则语法、条目数、MRS 解码异常时，
  只选择该来源经过当前解析与门槛检查的旧缓存。
- 版本、URL、时间、大小、解压和 SHA-256 检查失败则拒绝缓存。
- 全部生成、验证、编译成功才晋升候选原文；失败运行、空/错误响应、
  dry-run 不覆盖缓存。回退不刷新上次成功时间。恢复后自动使用新数据。
- 内部程序错误、缺失可执行文件、最终合并/编译失败仍停止，不伪装成来源失效。
- 缓存与成功生成产物一同提交，不依赖短期 Actions 附件过期时间；不新增历史 Release。

缓存 JSON 是 gzip/base64 包装，不是加密。仅用于公开来源，不得加入凭据或私有内容。
新增来源应同时补充 `validate_source_payload` 的逐来源验证与失败回退测试。

## 首次启用：没有逐源历史时

旧版本只保留合并后的产物，无法反推出每个来源原文。AI 来源失效且没有有效
原文缓存时，可以通过 `--published-baseline` 使用 **完整且已验证的旧 AI 组件**：

1. workflow 通过现有 `release_snapshot.py` 下载完整旧发布，验证资产哈希及最后上传的清单。
   下载/验证失败时不提供基线，正常新来源生成仍可继续。
2. 生成器再次检查完整快照哈希、文件安全性、AI 域名主集与 MRS 一致性及两个 Extra 格式一致性。
3. 原样沿用 `AI.list`、`AI.Extra.list`、`AI.mrs`、`AI.Extra.yaml` 四个文件；
   不混入部分新数据，不刷新时间戳。Ozon/去广告仍使用本轮有效来源生成。
4. 所有 AI 组成来源标记为「未使用本轮候选、来源新鲜度未知」，本轮 AI 候选不会晋升缓存。
   快照提交 SHA 仅证明基线身份，不代表 AI 上次获取时间；不伪造逐源历史。
5. 来源恢复并完整验证通过后正常生成 AI，建立逐来源缓存。

没有可信基线或基线损坏、不一致时失败关闭，保留上次发布。其他组件没有有效逐源
缓存时也失败，不擅自扩大整组替代范围。

## 状态与通知

`source-status.json` / `.md` 展示来源 URL、候选获取状态、是否用于产物、上次成功
时间、哈希及失败原因；错误中的本地临时路径脱敏。失败也保留 Actions 摘要和附件；
成功发布附带状态及 Release 说明。`success: false` 的候选不代表已经发布。

独立 `source-health` 检查在来源失效或整组应急回退时失败，使用现有 Actions 失败
通知提醒所有者决定修复、替换或等待；实际送达取决于用户 GitHub 通知设置。
它不阻止有效旧数据继续发布。CNB 仅在确认为同一 run、attempt、SHA 的 gen/publish
成功、且只有 source-health 失败时放行；不确定或其他失败拒绝同步。无权限/凭据扩张。
